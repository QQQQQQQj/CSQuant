# CSQuant 前端信息架构（FRONTEND_INFORMATION_ARCHITECTURE）

> V1 = Streamlit 单应用 9 页签（tab 而非 multipage：单用户看板切换更快、状态共享简单）；页面只调 services 层，禁止直查库、禁止写业务逻辑。
> 规范：中文界面；红涨绿跌；价格带 ¥；行情卡带新鲜度时间戳与质量角标(A绿/B蓝/C黄/D红)；时间展示 UTC+8。

### 2.2 💰 总资产与盈亏（FR-3/4）

KPI 行（总资产/总成本/浮盈/已实现/收益率/净注资）→ 净值曲线（plotly 折线，可切 7/30/90/全部）→ 双饼图（按品类、按平台计价分布，借鉴 csgo_investment）→ 收益构成瀑布（可选）。注资/撤资记录入口（防收益率污染）。

五档配色（极度恐慌深红/偏空浅红/震荡灰/偏多浅绿/极度贪婪深绿）；点击因子展开原始值与数据质量。

### 2.4 🔍 单品详情（FR-11 行下钻）

名称/图片/元数据（武器/磨损/稀有度/收藏品/存世量）→ 多平台报价卡（BUFF/悠悠/Steam/C5：在售价+量、求购价+量、价差%、质量角标）→ K线图（平台/周期切换，成交量副图——SteamDT 源提示无量）→ 涨跌指标条（1/7/30/180 天）→ 最新信号卡 → 操作（加自选/录入持仓）。

### 2.5 🧰 饰品筛选器（FR-11）

侧边栏筛选（关键词/品类/磨损/稀有度/价格区间/7日涨跌区间/流动性档位）→ 结果表（AgGrid：名称/价/1d/7d/30d 涨跌/成交量/在售数/spread/质量）→ 红涨绿跌着色 → 批量加自选。

### 2.6 📡 买卖信号（FR-8/9）

```
┌──────────────────────────────────────────────────┐
│ [立即生成] 筛选: [BUY▾][风险▾] 模型: signal-v1.0.0 │
│ ┌────────信号卡────────┐ ┌────────┐ ┌────────┐    │
│ │AK红线  BUY  Score 78 │ │...HOLD │ │...SELL │    │
│ │置信度71% 风险●●○ 仓位8%│ └────────┘ └────────┘    │
│ │理由: 趋势↑ 供需强…[展开]│                         │
│ └──────────────────────┘                          │
└──────────────────────────────────────────────────┘
```
信号卡要素：score 环、置信度、风险灯(L绿/M黄/H红)、建议仓位、理由折叠（展开显示逐因子贡献+当时数据快照时间）、「标记已人工执行」按钮（写 event_log，不自动下单）。

### 2.7 🧪 回测（FR-10）

参数表单（策略/区间/资金/费率/滑点档/universe）→ 运行 → 结果：KPI 表（总收益/年化/最大回撤/Sharpe/Sortino/胜率/盈亏比/换手/费后/基准对比）+ 权益曲线+回撤曲线 + 交易明细表 + 局限声明横幅（数据量不足时强制显示）。历史回测列表可复看。

### 2.8 🔌 数据源状态（FR-12）

三源健康灯（CSQAQ/SteamDT/Steam：状态/1h成功率/延迟/新鲜度/最近错误/熔断状态）→ 手动补采按钮 → event_log 最近 50 条（熔断/告警）。

### 2.9 ⚙️ 系统设置（FR-13）

密钥状态（已配置/未配置，不回显）、策略参数（权重/阈值，修改需输入新 model_version 并提示需回测验证）、费率表、采集频率（tier L1/L2/L3）、危险操作区（清空缓存/重置数据库，二次确认+写 event_log）。

## 3. 通用规范

- 组件：KpiCard / NavChart / SignalCard / Gauge(0-100) / QualityBadge / FreshnessTag；
- 交互：危险操作二次确认；成功/失败 Toast；加载骨架；数字千分位；
- 图表：plotly（streamlit 原生集成优于 pyecharts 的交互与维护）；
- 迁移预留：每个页签对应一个 services 调用，未来按 API_DESIGN Part 2 平移 FastAPI+React，组件↔端点 1:1 映射。
